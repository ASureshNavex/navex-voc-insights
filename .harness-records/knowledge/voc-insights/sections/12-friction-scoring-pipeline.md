## Step 1a-1d: segment scorecards

| Phase | What | Rules |
|---|---|---|
| 1 Scoring queries | Batches 1-4: complaints 30d, negative sentiment 30d, support cases 30d/90d, churn phrases 30d | ARR and segment filters at query time; never pre-filter to known accounts |
| 1 post-filter | AR4 exclusion list, require departure phrase, manual edge review | See 11 |
| 2 Score | Join batches on account_name; evaluation order AR4 -> AR1 -> AR2 -> AR3 -> AY1 -> AY2 -> AY3 | Exclude ARR 0/null; compute ratio, `arr_fmt` ($XK / $X.XM), `churn_language_detected` (AR4 only) |
| 3 Taxonomy | For every Red and Yellow account, in batches of 20 names: (L1, L3) pairs by distinct record count, 30 days, non-MISC | Top 5 distinct pairs; skip L3 = 'General' (1a) / L1 = 'General' (1b-1d) |
| 4 Verbatims | Complaint `fi.content` for all Red and top Yellow by ARR, batches of 20 | Complaint records only |
| 5 Summaries | 2-4 sentences: product area, impact, patterns (recurrence, urgency, multi-product, escalation) | Never mention the rule, counts, RYGG, Red or Yellow; AR4 leads with departure signal; no verbatims -> describe from chips; never fabricate |
| 6 Build JSON | Red, Yellow, AR4 verbatims (schemas below) | AR4 list sorted ARR desc; verbatims in query order |
| 7 Save | Three files with run date in the name; present files | |
| 8 WoW (1a only) | Diff against a supplied prior-week Red file; print new / exited Red | Skip silently if no prior file |
| KPI block | Red count and ARR with per-rule counts; Yellow count and ARR with per-rule counts; total ARR at risk | Printed in chat |

Completion gate: all batches run; taxonomy for every Red and Yellow; verbatims for Red (and top Yellow); three files written and presented; KPI printed; WoW printed if a prior file was given.

Output files: `NAVEX_RYGG_[<Segment>_]Red_Complete_<date>.json`, `..._Yellow_Complete_...`, `..._AR4_Verbatims_...` (Segment = MidMarket, SMB, Enterprise; none for 1a). Older Enterprise-below-50K name: `NAVEX_RYGG_Red_Complete_<date>_below_50_ent.json`.

Red JSON (Yellow is the same with `rating` Yellow, rules AY1-AY3, no churn fields):

| Part | Fields |
|---|---|
| `metadata` | report_name, run_date, window ("Last 30 days"), arr_filter, scoring_model ("NAVEX RYGG June 2026 v3 Final"), account_count, red_arr_total, red_arr_fmt, ar4_count, ar1_count, notes |
| `red_accounts[]` | account_name, rating, rule, arr, arr_fmt, cxm, segment, complaints_30d, neg_sentiment_30d, support_cases_30d, support_cases_90d, case_ratio_30d_vs_90d, churn_language_detected, churn_note, l1_l3_taxonomy [{l1, l3}], summary |
| AR4 file | `metadata` (report_name, run_date, window, arr_filter, account_count); `ar4_verbatims[]` {account_name, arr, arr_fmt, verbatims [{record_id, content}]} |

## Step 2: Red issue review (never produces HTML)

| Item | Rule |
|---|---|
| Inputs | Every `NAVEX_RYGG_*Red_Complete_*.json` (+ AR4 files for the reply only); stop if none |
| Query | Per unique Red account name, batches of ~150: Issues records grouped by status with count and latest timestamp |
| Open count | Statuses Open - Unresolved and Open - Health Data Action, plus blank status with activity within 90 days of run date |
| Classify | `open` if open_count > 0; `closed` if records exist but none open; `norecords` if none |
| Fields added per account | issue_status, issue_open_count, issue_total_count, issue_last_activity (YYYY-MM-DD or null), issue_open_hda_only |
| Metadata added | `issue_review` {review_date, source "Enterpret snowflake-issues", status_counts, open_statuses, blank_status_rule} |
| Output | Same file names under `red_with_issues/`; Yellow and AR4 files untouched; existing fields unchanged |
| Reply | Status counts per file and total; AR4 accounts with no open issue, and which have no records |
| QA | Same count and order per file; every account has all five fields; status_counts sum to account_count |

## Step 3: all-segments render

| Step | What |
|---|---|
| 0 Inputs | Up to 12 cohort JSONs, `Exec_Outreach_mapping.xlsx` (always required), issue data (optional) |
| 1 Merge | all_red / all_yel across cohorts; `ar4_lookup` = first AR4 verbatim per account |
| 2 Enrich | Live query in batches of ~90: account_owner, SPF, renewal date, region, segment (always re-query segment: JSON segment is blank for many > 50K accounts). NPS: most recent category per account |
| 3 Exec sponsor | From xlsx, normalized name match |
| 3b Issues | Load issue status; never query Issues here. Missing file -> column "Coming soon", no Issue filter, say so |
| 4 KPIs | Per enriched segment: Red count/ARR, Yellow count/ARR, total |
| 5 Sort | Red: AR4 first then ARR desc; Yellow ARR desc |
| 6-9 HTML | Layout, filters, columns, data attributes, JS, style tokens (see 13) |
| 10 QA | colspan 10; 4 tabs; `data-tier` on every row; grand total equals sum of loaded files; Red rows have open/closed/norecords, Yellow `unchecked`; chip counts equal status_counts; 4 issue filter options; file < 5 MB (~1.5 MB for 700+ accounts) |

New This Week: true if any of `wow_new`, `new`, `is_new_this_week` is true (field name varies by cohort).

## Domain track (weekly-voc-html-report)

1. Mode: A full (default), B segment filter, C region filter, B+C combined, D detail drill-through on request. Window fixed at 30 days; never prompt for it.
2. Per domain run Queries 2A-2G plus the full baseline series (see 10a).
3. Resolve any theme named General, Miscellaneous, Misc, Other or Unclassified: read its verbatims, synthesize a 2-5 word label; fallback "Mixed operational issues". Never render those labels.
4. Score (10a), compute trend flag and display thresholds, sort by band then 30-day volume.
5. Write narrative (customer experience only, no scoring language), then search Aha! with 2-3 queries from top themes for features / epics / initiatives (exclude ideas, pages, abandoned); max 4 items per domain.
6. Cross-cutting check: email/message delivery failure in the top 3 themes of >= 3 domains -> callout.
7. Render HTML, QA, deliver. PDF only on request, Playwright Chromium (A4 landscape, margins 12/10 mm, scale 0.75); wkhtmltopdf prohibited.

## Domain detail reports (domain-detail-reports)

| Item | Rule |
|---|---|
| Scope | Default: all Red and Yellow domains from the latest scorecard; any domain on request; all 14 -> confirm first |
| Window | Explicit `window_start = run_date - 30 days` to `run_date` with `toDateTime` bounds; never `now()`, so counts match the scorecard |
| Query D1 | Complaint records for the domain L1 with source, account, theme, `fi.content`, Salesforce links, case subject, issue type |
| Dedup | One row per `record_id`; themes collected into a list; record count must equal the scorecard complaint count |
| Does not | Re-score, re-run the scorecard or produce a rating |
